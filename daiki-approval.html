Daiki ERP — Approval Process & Expense Control System

A highly configurable approval engine built inside a multi-company ERP system for a manufacturing and engineering organization. It manages end-to-end financial and operational requests: payments, travel, expenses, advances, manpower requisitions, purchases, and budgets.

My role
Backend Developer (core module owner)
Replaced
Paper forms, emails, and Kissflow
Stack
Laravel 9 · MySQL · Redis · Docker

My Role

The old workflow was split across paper forms, emails, and a third-party low-code tool (Kissflow) that could not support complex branch- and designation-based approval rules. I owned the core backend of the replacement.

  • Designed and implemented the approval workflow engine
  • Built the request lifecycle system (approve / reject / forward / return / recall)
  • Developed the budget control and ledger system
  • Implemented the travel policy and expense calculation engine
  • Built the notification pipeline (email, push, SMS, WhatsApp)
  • Designed analytics and reporting endpoints
  • Built the RBAC model (~200 permissions across 65 controllers)

Key Challenges & Solutions

Problems I ran into while building the engine, and how I fixed them.

Complex Workflow Resolution

Multiple workflow definitions (branch, department, designation) caused inconsistent routing.

Solution: a unified 12-level precedence resolution engine.

Cross-Chain Condition Leakage

Step conditions bled across workflow chains that shared the same step order.

Solution: strict scope matching enforced per workflow chain.

Budgets on Legacy Data

Existing projects had no budget structure.

Solution: a backward-compatible validation layer with safe fallback paths.

Ledger Consistency Risk

A ledger write failure could roll back an approval.

Solution: ledger decoupled from transaction success, so a ledger failure never breaks the approval flow.

Cross-Company Policy Errors

The wrong company context was used in calculations and dashboards.

Solution: explicit request-owner-based scoping across all services.

Test vs Production Drift

Test chain execution did not match production behavior.

Solution: both unified through a shared chain-walker engine.
